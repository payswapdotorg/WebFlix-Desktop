# YouTube parity matrix — per-operation status, quota cost and user handoff

Owner: connectors lane (YOUTUBE-EXPAND, Phase 2). Reviewed against: docs/plans/work-orders/YOUTUBE-EXPAND.md (scope rows 1–5), docs/plans/audits/AUDIT-SOURCES.md §2/§8 (capability inventory + honest-unsupported list), ADR-0003 (YouTube-first, per-user identity, official surfaces only), contract-freeze §2 (binding shapes), docs/plans/phase3-platform-selection.md (next platforms; not this order's scope).

Status vocabulary: `supported` · `quota-constrained` (supported, but the daily-unit budget is the binding constraint and a first-class UX state) · `requires-auth` (needs a per-user OAuth grant) · `unsupported` (no official API exists — honest state, WebFlix-local substitute or user handoff only) · `blocked-by-policy` (prohibited by the YouTube API Services Terms/Developer Policies). The frozen §2.3 `CapabilityStatus` enum maps these onto UI states via the shell's honest-state vocabulary.

Quota costs are the official unit costs (default project budget 10,000 units/day): search-class reads 100 units, typical list reads 1 unit, writes ≈50 units. Source: https://developers.google.com/youtube/v3/determine_quota_cost and https://developers.google.com/youtube/v3/getting_started#quota. The connector keeps the precise per-operation model in `YOUTUBE_OPERATION_COSTS` + the dataApi ledger (MR-FD2); the frozen manifest carries the request-envelope approximation.

## Quota model and honest budget states

- Default project budget: 10,000 units/day (official). search.list costs 100 units — the dominant, binding cost (100 searches/day); list reads cost 1 unit.
- The dataApi client charges every attempt to a local ledger (successes and provider errors; pre-flight blocks and network errors charge 0) and exposes `SearchBudgetSnapshot { state: ok|low|exhausted, unitsRemainingToday, searchCallsRemainingToday, providerReportedExhaustion }`; low watermark = 500 units (5 searches).
- Provider-side `quotaExceeded`/`dailyLimitExceeded` marks the day exhausted honestly; `rateLimitExceeded`/HTTP 429 surfaces a typed RateLimitedError with the served Retry-After; nothing is retried silently and no degraded result is presented as success.
- The quota day resets on the provider's schedule (midnight Pacific Time per the official quota FAQ — https://developers.google.com/youtube/v3/faq#quota — while the local ledger rolls at the UTC day boundary; the UI copy says "next quota day" rather than claiming a reset instant the app cannot observe).

## Live-smoke status (recorded 2026-10-11, YOUTUBE-EXPAND sandbox)

1. **IFrame embed endpoint — LIVE-VERIFIED.** `curl -sSI https://www.youtube.com/embed/jNQXAC9IVRw` → `HTTP/2 200`, `content-type: text/html; charset=utf-8` (served 2026-10-11T04:17:03Z). Privacy-enhanced domain `https://www.youtube-nocookie.com/embed/jNQXAC9IVRw` → `HTTP/2 200`, `text/html; charset=utf-8`. Both official embed hosts serve the public-video player page to anonymous fetches from this sandbox.
2. **Data API v3 unauthenticated shape — LIVE-CAPTURED.** One live request to `search.list` without a key (`GET https://www.googleapis.com/youtube/v3/search?part=snippet&q=…&type=video&maxResults=1`) returned:
   ```json
   {
     "error": {
       "code": 403,
       "message": "Method doesn't allow unregistered callers (callers without established identity). Please use API Key or other form of API consumer identity to call this API.",
       "errors": [{ "message": "…same…", "domain": "global", "reason": "forbidden" }],
       "status": "PERMISSION_DENIED"
     }
   }
   ```
   This is the exact envelope the client's error parser reads (`error.errors[0].reason`); an unprovisioned key therefore surfaces as an honest typed provider error (`unavailable` state with the provider's own message) — never as fake results.
3. **Account-interactive flows (OAuth consent, connected-account live behavior):** fixture-tested; account session verified by TL2 operator-side; app-side OAuth live pending Google Cloud client ID (operator item).
